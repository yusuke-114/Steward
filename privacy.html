Safety & Privacy

Drive Claude Code on your Mac from Telegram on your phone

Last updated: 2026-09-26

Steward collects nothing

No analytics, no telemetry, no crash reporting, no phoning home of any kind. The only outbound request it initiates is to the Telegram Bot API — because that is its job.

This page is also the practical user guide for Steward. It explains what the app can do, what leaves your Mac, and what to check before you let a phone message control a desktop.

What stays on your Mac

The following is stored on your own machine. Steward never sends any of it anywhere:

A note about the bot token

This version stores it in plain text in your user preferences, readable by your macOS account but not encrypted. That token is equivalent to remote shell access to your Mac — treat it like a password. If you suspect it leaked, revoke and reissue it with /revoke at @BotFather. Steward removes the token from anything it shows in the Logs tab or in error messages.

What leaves your Mac

Steward is a bridge. It does not store, analyse or resell any message content — but messages do pass through two third parties:

  • Telegram — every message between you and the bot is carried by Telegram's servers. Their privacy policy applies.
  • Anthropic — what you send to Claude is delivered by the local claude process to Anthropic. That link is managed by Claude Code itself; Steward only hands over your text. Their privacy policy applies.

In other words: Steward has no server and no backend that its author can see. None of your data reaches the developer.

What Steward can do on your Mac

This is not a traditional privacy-policy section, but it matters more than one, so it goes here.

Steward runs as you, outside the sandbox. It can do what you could do at the keyboard: read and write files, run shell commands, reach the network. That is the feature, not a flaw — driving Claude Code remotely requires exactly those permissions.

Anyone who can message this bot can run any command on your Mac. The only thing standing in the way is the Telegram user ID allow list: messages from anyone else are dropped silently.

  • By default, every time Claude wants to act (edit a file, run a command) the request is pushed to your phone for approval.
  • Only tools on the allow list skip that step, and the default allow list is read-only (Read, Grep, Glob, TodoWrite).
  • A request nobody answers within 5 minutes is auto-denied, and you are told.

Requirements and setup

  • macOS 26.0 or later
  • Claude Code, installed and signed in
  • A Telegram bot token from @BotFather
  • Your numeric Telegram user ID from @userinfobot

Install with brew install --cask yusuke-114/tap/steward or download the ZIP from the project releases. Open Steward, paste the token and user ID, and press Save: Steward checks the token with Telegram before saving it. Add a project folder, press Connect, then send /status from Telegram.

Steward first asks your interactive zsh for claude, then falls back to ~/.local/bin, /opt/homebrew/bin and /usr/local/bin. If it still cannot find Claude Code, set the path in Settings.

How to use it

SendResult
Any textGoes to Claude Code
!commandRuns a shell command directly in the project folder
/projectLists your projects
/project nameSwitches project
/stop /status /helpStop, status and help

The ! prefix skips approval because it is treated as a command you typed deliberately. If you want the approval step, ask normally instead.

Sessions are continuous: switch projects, restart the app, or recover from a claude crash, and the conversation resumes from the last known session.

Distribution and limitations

  • Steward is distributed outside the Mac App Store because the macOS sandbox cannot run a user-installed claude command in the way this app needs.
  • One active session runs at a time. You can switch projects, but not run multiple projects in parallel.
  • Scoped rule matching, such as Bash(rake swiftformat), is passed to Claude Code as written. Steward does not validate how broad the match is.
  • There is no automatic updater in this version.

Invalid tokenSave rejects it and keeps the previously saved token. If a saved token stops working, Steward stops polling and shows the invalid-token status; verify it with BotFather
“Telegram is in use elsewhere”Another program, another Mac, or a webhook is using the same bot. Stop it (or delete the webhook), then press Connect again

How approvals work

Claude Code's headless mode runs as a subprocess and speaks a structured event stream. Approvals go through a PreToolUse hook: the hook blocks while POSTing the request to Steward's local endpoint, Steward pushes it to your phone, and your answer travels back the same way.

The timeout order is deliberate: Steward waits for you for 300 seconds, the hook's curl waits for 570 seconds, and Claude's hook timeout is 600 seconds. Steward has to time out first, so that a denial is a decision it made and logged.

Every failure falls toward denial. If the hook cannot reach Steward, the response is corrupt, or stdin never closes, the request is denied instead of hanging indefinitely.

What this does not involve

  • No personally identifiable information is collected
  • No cookies or tracking of any kind
  • No ads, no data shared with third parties
  • Not directed at children under 13
  • No accounts, no sign-up

Changes to this policy

If a future version changes how data is handled (adding optional log files, say), this page will be updated and the change noted in the release notes.

These claims describe the current app implementation and distribution notes: Steward has no analytics, telemetry, crash reporting, server component, or log files.
